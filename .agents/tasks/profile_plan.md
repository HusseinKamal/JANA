## Findings that shape the plan

- Compose resources resolve to `components-resources:1.7.0` (Compose UI resolves to 1.9.1). In 1.7.0, `stringResource` reads `androidx.compose.ui.text.intl.Locale.current` inside `DefaultComposeEnvironment.rememberEnvironment()` and caches with `remember(locale, theme, density)`. `Locale.current` is NOT observable, so changing the locale only takes effect where the tree is recomposed from scratch. This is why JetBrains' documented workaround (kotlinlang.org/docs/multiplatform/compose-resource-environment.html) is `expect object LocalAppLocale` + `key(locale) { content() }`.
- JANA already has `AppLanguage` + `LocalAppLanguage` + `expect applyLocale/saveLanguage/saveLanguageAndRestart/loadSavedLanguage` in `DS\commonMain\...\designsystem\AppLanguage.kt` with actuals in `DS\{androidMain,jvmMain,iosMain}\...\AppLanguagePlatform.kt`. Nothing in the app calls `saveLanguage` yet. Problems with the current actuals: JVM `saveLanguage` restarts the process (`exitProcess`), Android calls `AppCompatDelegate.setApplicationLocales` (on API 33+ this recreates `MainActivity`, a `ComponentActivity`, and the back stack is lost), iOS is a stub.
- `AppNavHost` (`NAV\AppNavHost.kt`) keeps the back stack in `remember { mutableStateListOf(...) }`, and `rememberEntryViewModelStoreDecorator()` (`NAV\EntryViewModelStoreDecorator.kt`) keeps per-entry `ViewModelStore`s in a remembered map cleared in `DisposableEffect.onDispose`. A `key(language)` around the nav host would therefore reset the app to Splash. Checked in navigation3-runtime 1.1.1 `DecoratedNavEntries.kt`: `onPop` fires only for keys no longer in the back stack, so disposing the whole NavDisplay does not call `onPop`. Hoisting back stack + store map + `SaveableStateHolder` above the `key` keeps every ViewModel (including `HomeViewModel.selectedTab = PROFILE`) alive across a language switch.
- `core/datastore` has `AppPreferences` (DataStore<Preferences>, registered `single` in `core/di/.../CoreModule.kt`) and `TokenRepository.clearSession()`. `feature/home` does not depend on `:core:datastore` yet (auth and splash do, via `implementation(project(":core:datastore"))`).
- Auth route for logout: `AuthRoute.Login(initialTab = "STUDENT")` in `NAV\Routes.kt`; `AppNavigator.replaceAll(route)` exists.
- Reusable courses domain: `CourseRepository.getCourses()/getCourseUnits(id)`, `GetCoursesUseCase`, `GetCourseUnitsUseCase`, `Course(totalLessons, completedLessons, isSubscribed)`, `CourseLesson(isCompleted, hasExam)`. `CourseUnitSection(unit, onLessonClick, isLocked)` in `HOME\tabs\courses\presentation\detail\components\` is already reused cross-package inside feature/home (teacher tab imports courses components). ## Design decisions

1. **Runtime locale = JetBrains `LocalAppLocale` pattern + `key(language)` at the app root, with navigation state hoisted above the key.** It is the only approach that works on Android, iOS and Desktop with resources 1.7.0 and needs no new dependency. Hoisting keeps the back stack, ViewModels and saveable state, so switching language leaves the user on the Profile tab without an Activity recreate or process restart.
2. **`AppLocaleManager` (core/designsystem, Koin `single` in `shared/.../di/KoinInit.kt`) is the single source of truth** for the language: `StateFlow<AppLanguage>` seeded from `loadSavedLanguage()`. It lives next to `AppLanguage` because the app root (shared module) and the feature both already depend on designsystem; core/datastore is not visible to `shared`.
3. **Language persists in the existing synchronous platform prefs (SharedPreferences / java.util.prefs / NSUserDefaults), not DataStore.** The root needs the language before the first frame to pick layout direction; DataStore is async and would flash LTR→RTL. `AppPreferences.language` stays unused (not touched).
4. **Notification preferences persist in DataStore** via new keys in `AppPreferences` (DataStore already set up). Platform permission request: no expect/actual exists → `// TODO: request POST_NOTIFICATIONS / UNUserNotificationCenter permission`.
5. **Profile ViewModels emit no strings**: errors are Boolean flags / enums (`ProfileFieldError`), Screens resolve text with `stringResource`.
6. **"Subscriptions" and "Teacher platform" rows switch to the existing Teacher tab** (it already shows courses, live subscription and chat) through a hoisted `onOpenTab: (HomeTab) -> Unit` lambda from `HomeScreen`; no new subscription screen (YAGNI).
7. **Edit profile success**: Edit screen shows the snackbar (non-blocking `launch`), waits `SAVED_FEEDBACK_DELAY_MS = 900L`, then `onBack()`; the Profile screen updates automatically because it observes the shared in-memory profile flow.
8. **Logout** = `LogoutUseCase` → `StudentProfileRepository.logout()` (mock `POST /api/v1/auth/logout`, `TokenRepository.clearSession()`, reset in-memory profile) → effect → `navigator.replaceAll(AuthRoute.Login())`.
